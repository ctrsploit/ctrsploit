# v0.27.2: CVE-2026-23111 nf_tables LPE

Changes since `v0.27.1`.

## Vul

### [cve-2026-23111](https://github.com/ctrsploit/ctrsploit/blob/v0.27.2/vul/cve-2026-23111/README.md) ([#383], [#384])

Aliases: `23111`.

New:

- Adds the CVE-2026-23111 Linux kernel nf_tables use-after-free local
  privilege escalation module, exposed via `ctrsploit vul 23111 exploit` and
  `ctrsploit vul 23111 checksec`.
- Drives a four-phase unprivileged LPE pipeline: UAF trigger → KASLR leak →
  heap leak (diagnostic) → control-flow hijack + escalation.
- Defeats KASLR with an unprivileged IDT-based arb-read leak and/or a
  `seq_operations` reclaim, selected per target.
- Supports three Phase-4 hijack strategies chosen by target profile and CPU:
  ROP pivot via `mov rsp,rbp`, `xchg eax,esp` pivot, and ret2usr shellcode.
  The ret2usr strategy is gated on the shared `pkg/cpusec` detector and
  aborts when the CPU advertises SMEP or SMAP, so the exploit and
  `ctrsploit env cpusec` agree on what the CPU advertises.
- Ships four per-kernel target profiles: `debian-6.12.8-1-amd64`,
  `ubuntu-6.8.0-79-generic`, `ubuntu-6.8.0-101-generic`, and
  `ubuntu-5.15.0-173-generic` (last vulnerable jammy build; ABI 174 is
  fixed). Profiles live in `nftables/target/` and adding a kernel means
  adding one `Target` literal.
- Adds a CVE-2026-23111 nf_tables UAF detection to `ctrsploit checksec auto`.
- Adds kernel prerequisite checks under
  `prerequisite/kernel/cve-2026-23111`, plus reusable
  `prerequisite/module` checks for kernel module loaded state and
  autoload availability.

Test:

- Adds e2e environment configs for the exploit and prerequisite modules with
  kernel-version-suffixed test env names, and README reproduction steps.

### [pkg/kernel-privesc](https://github.com/ctrsploit/ctrsploit/blob/v0.27.2/pkg/kernel-privesc/README.md) ([#383])

New:

- Adds the shared kernel-memory-write escalation stage, the kernel-memory
  analogue of `pkg/pipe-primitive`: a CVE provides a
  `KernelWritePrimitive` (how to write bytes to a kernel address), and this
  package owns the escalation methods (`modprobe_path`, `core_pattern`, …)
  that overwrite a kernel global and trigger a root shell as root from
  userspace.
- Generalized for reuse across multiple CVEs.

### [shocker](https://github.com/ctrsploit/ctrsploit/blob/v0.27.2/vul/caps/shocker/README.md) ([#382])

Aliases: `cap_dac_read_search`, `open_by_handle_at`.

New:

- Adds a `--cmd` / `-c` flag to the shocker exploit that runs a one-off
  command in the host filesystem cwd instead of dropping into an
  interactive shell.
- The command runs via `/bin/sh -c`, so pipes and redirections work, e.g.
  `ctrsploit exploit shocker -c 'cat /etc/shadow'`.
- Omitting `--cmd` preserves the original interactive-shell behavior.
- Warns and ignores `--cmd` when the target inode is a regular file rather
  than a directory.

## Env

### [cpusec](https://github.com/ctrsploit/ctrsploit/blob/v0.27.2/env/cpusec) ([#384])

Aliases: `cs`.

New:

- Adds the `ctrsploit env cpusec` subcommand, which reports the active
  CPU/kernel security mitigations for the running architecture. Fills a gap
  in the `env` suite, which had no CPU/kernel hardening coverage.
- x86-64 reports SMEP, SMAP, KPTI, IBT, KCFI, and FG-KASLR; arm64 reports
  PAC, BTI, KPTI, PAN, and MTE. Each row carries a one-line description of
  what the mitigation blocks.
- Detection is unprivileged userspace only: `/proc/cpuinfo` (runtime
  authoritative) plus kernel config from `/boot/config-$(uname -r)` with a
  `/proc/config.gz` fallback. Missing kernel config degrades gracefully to
  cpuinfo-only.
- Adds a reusable `pkg/cpusec` detector returning a `Mitigations` struct,
  consumed by the subcommand and by the cve-2026-23111 ret2usr strategy
  gate.

## Tool

### [tool](https://github.com/ctrsploit/ctrsploit/blob/v0.27.2/README.md#tool--convenience-tools) ([#386])

New:

- Adds the `ctrsploit tool` top-level command, alias `t`, as the home for
  small convenience tools used during penetration testing.
- Ships as a skeleton with no subcommands yet; individual tools will land
  under `ctrsploit tool <name>` in follow-up releases.

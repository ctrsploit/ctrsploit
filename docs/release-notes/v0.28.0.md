# v0.28.0: cve-2026-23111 container escape

Changes since `v0.27.3`.

## Vul

### [cve-2026-23111](https://github.com/ctrsploit/ctrsploit/blob/v0.28.0/vul/cve-2026-23111/README.md) ([#390], [#391], [#392], [#393], [#394], [#395])

Aliases: `23111`.

New:

- Adds `ctrsploit vul 23111 exploit escape`, the container-escape mode for
  the nf_tables use-after-free. It reuses the existing kernel write
  primitive to overwrite a designated worker thread's `task_struct` —
  `cred`/`real_cred` → `&init_cred`, `fs` → `&init_fs`, `nsproxy` →
  `&init_nsproxy` — so the escaped thread is REAL host root (uid 0 in
  `init_user_ns`, full capabilities) with host filesystem and all init
  namespaces, not namespaced root. The escapee resolves its own
  `task_struct` via the per-CPU `current_task`, blocks as a quiesced ROP
  target, and after the writes lands a host-root shell or command on the
  worker's stdio.
- Flags: `--command`/`-c` runs a host command via `/bin/sh -c` with a
  host-root shell as default; `--timeout` bounds a stuck worker (default
  `12m`). The mechanism rides the ordinary ROP pivot — no ret2usr — so it
  is unaffected by SMEP/SMAP/KPTI.
- Supported escape profiles: `ubuntu-6.8.0-79-generic`,
  `ubuntu-6.8.0-101-generic`, `ubuntu-5.15.0-173-generic` and
  `debian-6.12.8-1-amd64` (the Debian escape offsets are extracted from
  the `linux-image-6.12.8-amd64-dbg` vmlinux and byte-verified).
- Selects the chain-reclaim primitive per kernel by slab accounting:
  `msg_msg` where it shares the freed chain's slab (6.8), set names where
  the accounting differs (5.15.0-173 and 6.12.8-1) — determined from
  `kmem/kmalloc` tracepoint evidence per kernel.
- Markers: `cve-2026-23111-escape-ok <tid>` when the escapee observes the
  namespace swap; the e2e asserts the stronger host-filesystem proof
  (a file owned by real uid 0 containing `uid=0`).

Improve:

- Reliability of the shared arb-read/reclaim machinery the exploit rides:
  rejects dangling-victim dumps instead of assembling them into
  plausible-looking garbage, bails a read after three consecutive misses
  (callers retry with a fresh UAF), keeps decoy objects alive across the
  trigger window, requires the per-CPU base to read identically twice
  (assumed-NUL zeros previously let all-miss reads pass validation), and
  bounds `GetElemDump` with a wall-clock deadline so a stalled netlink
  dump cannot hang a worker for the whole run.
- Cuts the set-name arb-read round to 250 spray objects (was 5000, tuned
  for the bare-VM LPE): the escape's merge layer runs one spray cycle per
  byte position of every arb-read, so the 5.15.0-173-in-container resolve
  dropped from ~7 minutes to ~2 (the reclaim only needs to claim one slot
  freed ~21 ms after the trigger commit). The per-call round cap rises
  4→8 to keep the coverage; `CTRSPLOIT_23111_SET_SPRAY` still overrides.
- Clean teardown: the launcher/worker architecture plus a `do_exit` park
  tail lets the container exit without the previous terminal-wedging
  state; interactive runs still need `docker rm -f` when the parked pivot
  thread cannot be reaped (documented in the README).

Fix:

- Absorbs the Phase-2 genmask parity: the SET_B catchall element is
  dump-visible on only one side of `nft_genmask_cur()`, and which side a
  boot lands on is not stable — the same binary read the carried-over IDT
  gate on 17/17 leak attempts and then zero names on 52/53 attempts with
  an identical netlink sequence. `dumpSetBNames` now flips the generation
  once with a throwaway committed batch and re-dumps when a dump carries
  no names; the seq_ops spray makes no commits, so a wrong parity used to
  be retried into the ground with every round re-dumping the same
  invisible element.
- Surfaces namespace-worker spawn failures and non-zero worker exits.
  Previously the CLI reported success (exit 0, zero output) when the
  worker's `clone` failed — e.g. under Docker's default seccomp profile —
  because `os.Process.Wait` returns a nil error for non-zero exits.
- Relocates the `ubuntu-6.8.0-79-generic` park-hop gadget out of the
  `perf_trace_sched_numa_pair_template` static-branch region: its runtime
  bytes are patched when the tracepoint is disabled, so the ROP park
  never switched stacks and the guest panicked.
- Parity-sweeps the legacy hijack trigger: the catchall element's stuck
  abort-time genmask bit makes both walks into the victim parity-gated,
  so every trigger round now re-arms both walk paths.

Docs:

- Restructures the module README after the cve-2026-43500 layout: exploit
  scenario, check vulnerability (with a recording), reproduce (LPE and
  escape subsections), e2e test, and mitigation notes with the affected
  range and interim hardening.
- Adds three asciinema recordings rendered to SVG: `images/checksec.svg`,
  `images/privilege-escalate.svg` and `images/escape.svg`. The escape
  recording (casts `20..22`) installs the released binary on the VM host
  (pinned `v0.28.0-beta.1`, the first release shipping the escape
  subcommand) and `docker cp`s it into the minimal container, which ships
  neither `wget` nor `curl`.
- Makes the escape proof file OWNERSHIP, not its contents: `uid=0(root)`
  inside the proof file is not discriminating (a namespaced root prints
  exactly the same), the container runs as uid 1000, so only an
  `init_cred` write leaves a root-owned file on the host. The README and
  the recorded demo now verify with `ls -ln`.
- Drops `--security-opt apparmor=unconfined`: the escape completes under
  Docker's default AppArmor profile (verified on 6.8.0-101 with only
  `seccomp=unconfined`).
- Corrects the Phase-4 strategy docs: the ret2usr path is implemented but
  no shipped profile selects it — all four targets set `Ret2Usr` false,
  and KPTI NX-marks user pages even without SMEP, so `ubuntu-6.8.0-101`
  rides the `xchg eax, esp` pivot.
- Flips the cve-2026-23111 container-escape cell in the root and `vul/`
  support tables, and refreshes `modules.json` (registers `cve-2026-23111`
  with alias `23111`, plus the `cpusec` checksec module) via
  `make update-modules-json`.

Test:

- Adds `docker-escape-*` e2e coverage for `ubuntu-6.8.0-79-generic`,
  `ubuntu-6.8.0-101-generic`, `ubuntu-5.15.0-173-generic` and
  `debian-6.12.8-1-amd64`, plus a `default-6.8.0-101` env asserting that
  Docker's default seccomp profile blocks the exploit cleanly with
  `operation not permitted` and nothing reaches the host filesystem.
- Stops each escape env at the host-side proof line via `stop_flag`: the
  parked D-state worker can wedge the guest after the result is already
  printed, which previously burned the remaining retries on a finished
  run.

## E2E

### [e2e.sh](https://github.com/ctrsploit/ctrsploit/blob/v0.28.0/test/e2e/e2e.sh) ([#392])

New:

- Adds a `retries` field to `e2e.yml` entries so boot-correlated flakes
  (KASLR-leak misses on some boots) are absorbed by re-booting the dqd VM
  instead of failing the run.

### [dqd.sh](https://github.com/ctrsploit/ctrsploit/blob/v0.28.0/test/e2e/dqd.sh) ([#393])

Fix:

- Makes `stop_flag` a real gate: the output reader loop ended at EOF when
  the ssh session died and the function fell through to `rm`'s exit status
  `0`, so any env with a `stop_flag` was recorded green even when its test
  never printed the flag. Success is now reported only when the flag
  actually appeared; otherwise the remote command's exit status
  propagates. This also fixes the pre-existing `cve-2020-15257` env, which
  has used this branch all along.

## Build

### [Dockerfile_dev](https://github.com/ctrsploit/ctrsploit/blob/v0.28.0/Dockerfile_dev) ([7e0e618])

Fix:

- Moves the dev/release build image base from `golang:1.24-bullseye` to
  `golang:1.24-bookworm`: Debian 11 LTS ended 2026-08-31 and its security
  updates were pulled from the mirrors, so `make binary` failed with apt
  404s (the v0.28.0-beta.1 release CI hit this). The apt-mirror rewrite
  now also handles the deb822 `sources.list.d/debian.sources` layout,
  which bookworm images ship instead of `/etc/apt/sources.list`.

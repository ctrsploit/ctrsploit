# v0.27.3: ptrace injection primitive

Changes since `v0.27.2`.

## Pkg

### [ptraceinject](https://github.com/ctrsploit/ctrsploit/blob/v0.27.3/pkg/ptraceinject/ptraceinject.go) ([#389])

New:

- Adds the reusable `pkg/ptraceinject` package, exporting `Inject` and
  `GetIp`. `Inject(pid, shellcode)` ptrace-attaches to a target process,
  overwrites the code at the program counter with caller-supplied
  shellcode, lets it run (the shellcode forks; the parent traps via int3
  so it can be restored, the child is detached to run freely), then
  restores the target's original code and registers so it continues
  unaffected. The flow is payload-agnostic: the same primitive is reused
  by cap_sys_ptrace escapes (reverse shell, command exec, …).
- This eliminates duplicated injection logic across ptrace-class
  vulnerabilities. Downstream vulns (e.g. ctrsploit-pro's
  `runc-tracescape`) can call `ptraceinject.Inject(pid, shellcode)`
  directly instead of copying `inject` and the arch-specific register
  helpers.

Fix:

- Restores the target's original code and registers on the error path.
  Previously, if `Inject` failed after overwriting RIP with shellcode
  (e.g. an unexpected wait status at the fork-event check), the deferred
  `PtraceDetach` would resume the target with shellcode still at RIP,
  corrupting or killing it. Now a `restored`-guarded defer pokes the
  original code and registers back before detach, so the target resumes
  unaffected even on failure.
- Tolerates intervening signal-delivery stops before the int3 trap. The
  detached child's exit generates a SIGCHLD to the parent (tracee) that
  can arrive as a signal-delivery-stop before the int3 SIGTRAP, causing
  a race (`expected int3 SIGTRAP, but got: SIGCHLD`). The wait now loops
  past such stops, re-injecting the signal, until the int3 trap is
  reached. This fixes ~50% flakiness in the KVM e2e environment.
- Restores original code at the poke site (original RIP), not at the
  trap RIP. Removes a dead `PtraceGetRegs` call and a stale comment that
  claimed the trap-time registers were needed for restoration.

## Vul

### [sys_ptrace/pid_host](https://github.com/ctrsploit/ctrsploit/blob/v0.27.3/vul/caps/sys_ptrace/pid_host/exploit.go) ([#389])

Refactor:

- `pid_host.Exploit` now calls `ptraceinject.Inject` and
  `ptraceinject.GetIp` instead of its private `inject`/`getIp`. The
  private `inject`, `getIp`, and arch-specific `getPC` helpers
  (`reg_amd64.go`, `reg_arm64.go`) are removed from `pid_host` and live
  in `pkg/ptraceinject`. `Exploit` behavior is unchanged.
